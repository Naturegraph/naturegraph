| Symptome                      | Origine probable                                           | Action                                                                                       |
| ----------------------------- | ---------------------------------------------------------- | -------------------------------------------------------------------------------------------- |
| 1. App necessite refresh      | React Query `refetchOnWindowFocus: false` + staleTime 5min | **Fixe** : focus refetch active, staleTime baisse a 60s                                      |
| 2. Session instable           | Auth listener Supabase                                     | Deja fixe en V1.0.4 (session persistante par defaut). Pas de regression observee. A monitor. |
| 3. Perte d etat authentifie   | Hydration React + cookies tiers                            | Pas de cas reproductible documente. A monitorer en V1.1.3.                                   |
| 4. Features intermittentes    | Race conditions API + refresh stale data                   | **Devrait etre attenue** par le focus-refetch active.                                        |
| 5. Routing landing apres auth | PublicRoute en place                                       | **Deja resolu** dans le code : `PublicRoute` redirige connectes vers `/home`.                |
| 6. Vision web-app fluide      | Architecture                                               | Convergence sur la duree, suivi V1.1.3 / V1.1.4.                                             |

**A confirmer en beta apres V1.1.3** : si les symptomes 1, 3, 4 persistent malgre
le focus-refetch, ouvrir un ticket NG-004B pour audit service worker + cache
PWA + auth hydration.

### V1.2.0 - Carnets d observations (MINOR)

**Contenu structurant** (NG-005 + NG-006) :

- Mode "Carnet d observations" actif persistant
- Etat brouillon sauvegarde (localStorage + sync Supabase)
- Multi-especes par sortie terrain + categorisation auto
- Statuts : brouillon, actif, termine, publie, archive
- Publication = 1 carnet -> 1 post enrichi dans le feed
- Reutilisation d un carnet existant (option C)
- Compteur d individus par espece
- Backward compatibility avec posts simples (1 obs = 1 post reste possible)

**Migrations DB** :

- Nouvelle table `observation_notebooks` (uuid, user_id, name, status, started_at, finished_at, metadata jsonb)
- Nouvelle table `notebook_observations` (notebook_id, species_id, count, rank)
- Vue compat : un carnet publie genere un `post` agrege

**Dependances et risques** :

- Refactor backend important (data model 1 -> N)
- Risque feed casse si mal integre (lecture stricte du contrat MockPost)
- Mobile UX terrain : flow simple, < 3 taps pour ajouter une espece
- Categorisation auto via `taxonomic_group` (deja en BDD)

**QA obligatoire** :

- Creation carnet desktop + mobile + PWA offline
- Persistance brouillon (fermeture navigateur, perte reseau)
- Publication carnet + affichage dans feed
- Compatibilite zero regression sur partage simple

**Annonce** : in-app obligatoire + force-logout NON (additif).

(NG-001, NG-002, NG-008, NG-009, NG-010) sont corriges dans le code prets
pour V1.1.3. NG-004 a une attenuation directe (focus-refetch) + sous-plan
en cas de persistance.

qui represente le saut V1.2.0 et la differenciation produit forte vs les
reseaux d observation classiques.

# V0.7.13 : tout s'affiche sans refresh (feed, commentaires, reactions) + etape 3 restauree

## 1. Le feed / les compteurs ne se rafraichissaient jamais tout seuls (bug de fond)

Symptomes Nicolas : "quand ma publication est partagee je ne la vois pas directement
sur le fil", "je dois refresh pour voir mon commentaire / le compteur".

Cause racine : le feed AFFICHE sur /home utilise `useInfiniteFeed` -> cle
`['feed-infinite', ...]`. Or publications, echanges et reactions invalidaient
`['feed']`. Et `invalidateQueries({ queryKey: ['feed'] })` NE matche PAS
`['feed-infinite', ...]` : le match se fait segment par segment, et 'feed' !=
'feed-infinite'. Resultat : le fil reellement affiche n'etait JAMAIS invalide apres
une action -> il fallait refresh a la main.

Fix : helper `invalidateFeeds(queryClient)` (dans `useFeed.ts`) qui invalide les DEUX
prefixes (`['feed']` ET `['feed-infinite']`), branche partout ou on invalidait
`['feed']` :

- `useContributePostSubmit` (publication) -> le post apparait tout de suite.
- `useEchanges` (publier / supprimer un echange + realtime) -> compteur 💬 a jour.
- `usePost` (reactions, suppression de post, ajout au carnet) -> vues coherentes.

Les commentaires et reactions avaient DEJA l'affichage optimiste + rollback ; c'est
la propagation vers le FEED (compteurs, apparition) qui etait cassee par le mismatch
de cle.

## 2. Rencontre : etape 3 restauree apres un reload (au lieu de 2)

Le brouillon plafonnait volontairement la reprise a l'etape 2 ("sans photos
persistees on ne peut pas valider l'etape 3"). Cette raison n'existe plus depuis que
les photos sont persistees (NG-038, draftPhotoStore) : on restaure donc l'etape reelle
(bornee au total d'etapes). Au reload de reprise, on revient exactement ou on etait.

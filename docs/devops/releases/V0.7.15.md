# V0.7.15 : echecs d'action visibles (C6) + retry auth des queries (C1)

Avancement du plan de fiabilite (`PLAN_FIABILITE_RESILIENCE_2026-08.md`).

## C6 : plus aucun echec d'action silencieux

Retour Nicolas : "je publie mon commentaire mais il n'est jamais enregistre",
"idem pour les reactions". Les mutations avaient l'affichage optimiste + rollback,
mais en cas d'echec serveur reel l'optimistic disparaissait **sans message** ->
impression que "ca n'a pas marche" sans savoir pourquoi.

Ajout d'un **toast d'erreur** sur l'echec (en plus du rollback optimiste et de la
capture Sentry deja en place) :

- `usePublierEchange` (commentaire) : "Ton message n'a pas pu etre publie" (persistant).
- `useBasculerReactionEchange` (reaction d'echange) : "Ta reaction n'a pas ete enregistree".
- `useToggleReaction` (reaction de post) : idem.

## C1 : les queries ne meurent plus en silence sur un 401 (token gele apres veille)

React Query ne retentait JAMAIS les 4xx. Or au retour de veille, `autoRefreshToken`
(timer) a ete gele -> le JWT expire -> la query part avec ce token -> 401 -> echec
silencieux -> page vide jusqu'a un refresh manuel (cause R1 du plan).

Desormais, sur une erreur d'auth (401 / 403 / PGRST301 / JWT expired), on tente **un**
`refreshSession()` (non bloquant) puis **un** retry -> la query repart avec un token
frais. Une seule tentative (pas de boucle). Les 5xx gardent leur retry x3 ; les autres
4xx ne retentent toujours pas.

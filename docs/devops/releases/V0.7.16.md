# V0.7.16 : anti-fantome (posts.status pending->published) + splash mobile-only

## 1. Anti-fantome / anti-fausse-notif (C4 Phase 2 du plan de fiabilite)

Le pipeline creait le post AVANT ses photos ; un submit interrompu laissait un post
"fantome" (sans media) qui apparaissait au feed et declenchait "X a publie" -> la
fausse notif "9 nouvelles puis 0". Le va-et-vient (V0.7.8-0.7.12) a deja fortement
reduit le cas ; cette release l'elimine a la source.

### Base de donnees (deja applique en prod + verifie)

Migrations `20260810_posts_pending_status_antifantome.sql` + `..._gc_pending_posts_...`:

- `posts.status` autorise desormais `pending` (contrainte elargie, additif).
- Les triggers `notify_on_new_post` et `update_user_posts_count` (deja ecrits pour le
  flux pending->published, ne s'appliquant qu'a `published`) sont rebranches sur
  INSERT **+ UPDATE** de statut (et DELETE pour le compteur). Garde anti re-notif sur
  simple edition d'un post deja publie.
- **Cron `gc_pending_posts` (toutes les 10 min)** : un `pending` de +5 min AVEC media
  = flip rate -> **republie** (rien perdu) ; un `pending` de +30 min SANS media = vrai
  orphelin -> **supprime**.

### Client

- `postService.createPost` respecte un `status` fourni (defaut `published`).
- `useContributePostSubmit` cree le post en `pending` quand il y a des photos, puis le
  passe `published` APRES l'upload (flip). Post texte (sans photo) = `published` direct.
- Le feed + le digest E2 filtrent deja `status='published'` -> un `pending` n'apparait
  jamais et ne notifie jamais. Si le flip echoue, le cron GC republie le post (il a des
  medias) : aucun post legitime perdu. Bonus : un doublon `pending` sans media issu du
  retry reseau de createPost est nettoye par le GC.

**Non-cassant** : les 161 posts existants restent `published`, comportement identique.
Post texte publie exactement comme avant.

## 2. Splash video : mobile / PWA uniquement

Retour Nicolas : le carton creme du BootSplash s'affichait aussi sur desktop et
polluait visuellement (entre le loader et le squelette). Il ne sert qu'au lancement
mobile / PWA. `App.tsx` : le splash est desormais gate sur un viewport mobile
(`max-width: 767px`) ; sur desktop il ne s'affiche plus du tout (l'app rend
directement, chaque route gere son propre loader). Sur mobile, inchange (1er
lancement de session seulement, via le flag sessionStorage).

## Changements front

### Migration searchService.ts

- `searchSpecies()` delegue maintenant au RPC `search_taxonomy()` au lieu de
  query directe sur `species_master`. Interface `SpeciesHit` preservee pour
  back-compat des composants existants (SearchPanel, etc.).
- Nouvelle fonction `searchTaxonomy()` avec interface complete `TaxonomyHit`
  (rang, drapeaux territoire, popularite, iNat ID).
- Mapping `class` iNat <-> `taxonomic_group` legacy pour preserver l UI.

### EncounterStep2 (sélecteur d espece)

- Source : `searchTaxonomy()` au lieu de `searchSpecies()`.
- Toggles checkboxes cumulatifs `includeSpecies` + `includeFamily` (avant radio).
- Si combo active : section header "FAMILLES" en haut + "ESPÈCES" en bas
  (au lieu de melanger les resultats).
- Badge `Famille` visible dans les resultats + dans les rows du carnet.
- `ObservationEntry.species` ajoute `rank?: 'species' | 'family'` (additif).
- 8 categories dans le filtre `taxonomic_filters` (vs 5 auparavant).

### FeedFilterPanel (filtres feed Home)

- Categories etendues : Arachnides + Mollusques + Poissons ajoutees aux 5
  classes initiales.

### Footer global (MainLayout)

- Ajout liens `<Link to="/legal">` et `<Link to="/privacy">` (visible partout
  dans l app authentifiee). Demande Nicolas : "doit etre visible partout
  landing et dans panneau parametres".
- Attribution "Donnees taxonomiques : iNaturalist (CC-BY 4.0), GBIF (CC0),
  Wikidata (CC0)".

### SettingsLegalDocView

- Sections CGU passees de 6 a 7 (ajout "Sources de donnees et attribution").
- Sections Privacy passees de 11 a 12 (ajout "Sources tierces et sous-traitants").
- Contenu identique entre app et pages publiques (cohenrence).

### Em-dashes retires

- Conformite regle CLAUDE.md : aucun em-dash (—) ni en-dash (–) dans le
  contenu user-facing. Replaces par `:` dans les sections legales (FR + EN).

### Bug fix seed : iconic_taxa filter

Le filtre `/v1/taxa?iconic_taxa=X` de l API iNat ne fonctionne pas correctement
(renvoie 1000 familles globales identiques pour chaque classe). Nouvelle strategie :

- Fetch global sans `iconic_taxa` (max 80 pages de 100 = 8 000 familles globales
  par place_id).
- Filter cote PowerShell via `taxon.iconic_taxon_name` pour assigner la bonne
  classe a chaque famille.

### Migrations SQL

Aucune nouvelle migration en V1.1.0 (toutes les migrations sont dans V1.0.5).
Le travail V1.1.0 est purement code applicatif + seed BDD.

Moyen. Touche le flow critique de publication (sélecteur d espece) :

- Recherche espece : passe d une table 5k a une RPC 42k entries. Indexes
  GIN trigram doivent etre performants (deja verifies en V1.0.5).
- Family fallback : nouveau flow utilisateur. Si bug, fallback sur la
  recherche espece classique.
- `species_master` legacy reste intact en BDD (back-compat posts existants).

- Temps de reponse `search_taxonomy()` (cible < 200ms p95)
- Taux d adoption du toggle "Famille seulement"

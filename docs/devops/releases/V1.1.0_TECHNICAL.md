### Bug fix seed : iconic_taxa filter

Le filtre `/v1/taxa?iconic_taxa=X` de l API iNat ne fonctionne pas
correctement (renvoie 1000 familles globales identiques pour chaque classe).
Strategie revisitee :

- Fetch global sans `iconic_taxa` (max 80 pages de 100 = 8 000 familles
  globales par place_id).
- Filter cote PowerShell via `taxon.iconic_taxon_name` pour assigner la
  bonne classe a chaque famille.

### RPC `search_taxonomy()` v4

Iterations successives durant les tests Nicolas :

- **v1** : initial, ranks species/family/order
- **v2** : ajout colonnes `available_in_fr/ca` + `inaturalist_id` au retour
- **v3** : tentative de matching "famille via especes" pour fixer "mygale".
  Correlated subquery sur 42k especes -> timeout 6s cote front. **Rollback.**
- **v4** (actuelle) : retour a v2 simple + boost famille (rank species=1,
  family=1 au lieu de species=1, family=3). Les familles remontent quand
  leur match_score est bon (ex: Calopterygidae score 0.529 pour "calopteryx").
  Plus aussi `ILIKE '%query%'` (contains) sur common_name pour matcher
  partiellement.

### Limitations connues

- Familles sans `common_name_fr` (~70% sur 3 444) : non-trouvables par nom
  vernaculaire. Ex: "mygale" ne trouve pas Theraphosidae car
  `Theraphosidae.common_name_fr = NULL`. Script d enrichissement disponible
  (`scripts/enrich-families-common-names.ps1`), a executer en post-deploy.
- Species ne sont pas linkees a leur famille via la colonne `family`
  (toujours NULL car iNat species_counts API ne fournit pas les ancestors).
  Le matching "famille via species" sera fait en V1.2.0 via parent_id
  resolution.

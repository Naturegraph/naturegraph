# V1.2.14, hotfix securite RBAC (RLS anon)

Date : 2026-06-15
Type : hotfix (DB / RLS), sans changement front
Branche : hotfix/rbac-anon-rls

## Probleme

La migration RBAC V1.2.13 (`20260612_rbac_roles.sql`) a introduit deux policies de
lecture en role `public` qui appellent `is_admin()` :

- `admins_read_all_profiles` sur `public.profiles`
- `admins_read_all_admin_users` sur `public.admin_users`

Or `is_admin()` n'est pas executable par le role `anon`. Consequence : un visiteur
**anonyme** (mode invite, feed public, profils publics) recevait
`ERROR: permission denied for function is_admin` des qu'une requete touchait `profiles`
(ex. le feed, qui embarque l'auteur via `author:profiles(...)`). Le feed public et les
profils publics etaient donc casses pour les visiteurs non connectes.

Ce n'etait pas une fuite de donnees (aucun acces supplementaire accorde), mais une
regression fonctionnelle bloquante pour les invites.

## Correctif

1. **Restreindre toutes les policies admin au role `authenticated`** (au lieu de `public`).
   `anon` n'evalue donc plus jamais `is_admin` / `can_moderate` / `is_super_admin` : plus
   d'erreur de permission. Les lectures publiques (profils publics, catalogue d'especes,
   quota beta, insertion waitlist) restent intactes via leurs propres policies, qui ne
   dependent pas de ces fonctions.
2. **Reduction de surface RPC** :
   - `current_admin_role(uuid)` (renvoie le role en clair) n'est plus expose du tout
     (`REVOKE EXECUTE ... FROM anon, authenticated`) : il n'est appele qu'en interne par
     les helpers SECURITY DEFINER.
   - `is_super_admin(uuid)` et `can_moderate(uuid)` ne sont plus executables par `anon`.
   - `authenticated` conserve `is_admin` / `can_moderate` / `is_super_admin` (necessaires
     a l'evaluation des policies cote staff).

## Verification (prod + dev)

- Anon : lecture `profiles` / `posts` / `taxonomy_nodes` sans erreur ; le profil interne
  (natugraph) reste invisible (0 ligne).
- Super_admin authentifie : `is_admin() = true`, voit tous les profils (dont natugraph).
- RLS active sur les 9 tables touchees ; aucune policy permissive (`USING true`) introduite.

## Rollback

Re-pointer les policies sur le role `public` et re-`GRANT EXECUTE` aux roles concernes.
Aucun changement de schema ni de donnees, reversible instantanement.

## Audit memory leaks (etat actuel)

### Ce qui etait DEJA propre

| Pattern             | Statut | Detail                                        |
| ------------------- | ------ | --------------------------------------------- |
| createObjectURL     | OK     | revokeObjectURL partout (3 fichiers concerns) |
| addEventListener    | OK     | removeEventListener systematique (35 fichiers) |
| Supabase Realtime   | OK     | removeChannel au unmount (notifications)      |
| AuthContext sub     | OK     | subscription.unsubscribe au unmount           |
| IntersectionObserver| OK     | observer.disconnect au unmount (ImageSlider)  |

### Ce qui leakait silencieusement

**React Query sans `gcTime` explicite**.

- Default 5 min apres que personne n utilise une query
- MAIS avec des keys distincts par user / post / session, ca s accumule
  silencieusement sans declencher d alerte
- 30 min d usage normal -> 50+ entrees de cache zombies en memoire heap

---

## Fix V1.1.6

Modification de `src/lib/queryClient.ts` :

```ts
queries: {
  staleTime: 5 * 60 * 1000,
  gcTime: 10 * 60 * 1000, // V1.1.6 - explicit
  // ...
},
mutations: {
  retry: false,
  gcTime: 5 * 60 * 1000, // V1.1.6 - explicit
},
```

**Pourquoi 10 min queries / 5 min mutations** :

- Assez court pour liberer la memoire proactivement
- Assez long pour eviter les refetch inutiles si l user revient sur une
  page (navigation typique : 1 a 5 min entre 2 visites du feed)
- Mutations plus courtes : le context onMutate n a pas vocation a
  rester en cache au-dela de la mutation elle-meme

**Resultat attendu en prod** :

- Plateau memoire (sawtooth pattern) au lieu de croissance lineaire
- Le garbage collector React Query se declenche desormais a intervalle
  fixe au lieu d attendre l unmount du dernier observer

---

## Limites de ce fix

Ce fix attenue le symptome principal (heap qui grandit) mais ne couvre
pas tout :

1. **AbortController quasi-absent** : les fetch en cours quand l user
   navigue ailleurs continuent en background. Pas un memory leak
   classique mais gaspille du reseau et peut causer des warnings React
   "setState on unmounted component".
2. **Lazy chunks accumules** : normal mais on n a pas de strategie de
   dechargement.
3. **Pas de telemetrie prod** : Sentry est installe (`@sentry/react`)
   mais Performance Monitoring n est pas active -> on n a pas de
   visibilite sur la memoire reelle chez les beta-users.

A traiter en V1.2.0 (NG-004B) :

- AbortController systematique sur les fetch dans services/
- Sentry Performance + Web Vitals tracking
- Chrome DevTools heap snapshots manuels sur les scenarios critiques

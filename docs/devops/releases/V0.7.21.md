# V0.7.21 : residu splash regle pour de bon (un seul loader -> squelette)

Suite du rollback 0.7.19 (black screen mobile). Cette fois valide sur la PREVIEW
DEVELOP (mobile + desktop, par Claude et Nicolas) AVANT toute prod.

## Le probleme

Au lancement / refresh, DEUX ecrans de chargement s'enchainaient : le loader d'auth
(le "vrai", conserve) PUIS un deuxieme loader (le Suspense de route via AppLoader).
Sur desktop = un carton video ~1s a chaque refresh ; sur mobile = une video en 2e.

## Le fix

1. `src/router.tsx` : le fallback du Suspense de page (`LazyPage`) passe de
   `<AppLoader size="md" />` a **null**. Le chunk de page se charge tres vite (souvent
   deja pret pendant le splash) et chaque page a DEJA son propre etat de chargement
   (Home -> squelette du feed). Resultat : un seul enchainement **loader -> squelette**,
   plus de deuxieme loader intermediaire.
2. `src/components/ui/AppLoader.tsx` : la video de marque ne s'affiche QUE sur viewport
   mobile (<=767px) ; sur desktop, spinner discret. Le comportement MOBILE reste
   identique a l'existant stable -> aucun risque de black screen (contrairement a
   0.7.18 qui avait retire la video sur mobile aussi).

## Verification (methode corrigee)

Deploye sur la preview develop, verifie dans le navigateur (Claude) en viewport MOBILE
et DESKTOP : rend complet, 0 erreur console, aucun ecran noir. Puis valide par Nicolas
sur mobile reel AVANT promotion prod. Lecon de l'incident 0.7.18 : tout changement du
chemin de rendu/loader est teste sur mobile (preview) AVANT prod.

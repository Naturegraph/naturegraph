## Resume

Professionnalisation de la gestion des roles admin (RBAC). Ajout de deux roles
(`equipe_produit`, `developpeur`), enforcement role-aware au niveau RLS (plus seulement
dans l'UI), et attribution directe de role par le super_admin via une RPC atomique.

Aucun changement visible pour les utilisateurs standards. Seul le super_admin
(`Admin.naturegraph`) avait et conserve l'acces au panneau admin.

## Modele de roles

- `super_admin` : tout (gestion des roles, ban, suppression, taxonomie)
- `moderator` : moderation + beta + suspension (`can_moderate`)
- `support` et `equipe_produit` : acces panneau en LECTURE SEULE (RLS)
- `developpeur` : AUCUN acces panneau (tag technique). `is_admin()` l'exclut
- `migrateur` : utilisateur standard, aucun acces

## DB (migration 20260612_rbac_roles.sql)

- CHECK `admin_users.role` etendu (+ equipe_produit, developpeur)
- Contrainte `UNIQUE(user_id)` (1 role par user, vrai upsert)
- Helpers `current_admin_role` / `is_super_admin` / `can_moderate` (SECURITY DEFINER, search_path fixe)
- `is_admin()` reecrit : acces panneau aux roles staff, EXCLUT developpeur
- Lecture du roster admin + de tous les profils pour le staff (badges + comptes internes visibles dans /admin)
- Ecritures destructives resserrees a `can_moderate` (moderation, beta, admin_actions) ; taxonomie a `super_admin`
- RPC `admin_set_user_role(p_target, p_role)` : assignation atomique, verifie super_admin, anti-lockout

## Front

- `useIsAdmin` : nouveaux roles + helpers (`canModerate`, `isProductTeam`, `isDeveloper`), `isAdmin` exclut developpeur (defense en profondeur)
- `AdminUsers` : modale "Gerer le role" (assignation de n'importe quel role via la RPC), badges colores par role, onglets (Equipe / Developpeurs / Migrateurs), suspension gatee `canModerate`, gestion des roles gatee `super_admin`

# Release V0.0.8 : robustesse des liens d'invitation (technique)

> Date : 2026-07-01 · Tag : `v0.0.8` · Branche : `main` (prod)
> Precedent : `v0.0.7`
> Force-logout : NON · Migrations : 0 · Notif in-app : non

Correctif cible suite aux premieres vagues d'invitation. Quand un lien
d'invitation / magic link est deja consomme (les scanners anti-spam Gmail/Outlook
pre-cliquent les liens) ou expire, l'utilisateur atterrissait sur un ecran de
connexion sans explication (voire un ecran vide percu). Il repart maintenant
proprement sur l'inscription libre.

## Robustesse des liens d'invitation

- `src/lib/authUrlNotice.ts` : `captureAuthUrlError()` capture l'erreur d'auth
  presente dans le hash de l'URL (`#error=access_denied&error_code=otp_expired`)
  AU BOOT (premiere ligne de `main.tsx`, avant que Supabase ne nettoie le hash),
  pose un flag, nettoie l'URL. `peekInviteExpired()` / `consumeInviteExpired()`.
- `AuthPage` : quand le flag est present, l'ecran auth demarre directement sur le
  formulaire d'INSCRIPTION (acces ouvert : l'invite n'a pas besoin d'un lien, il
  cree juste son compte) et affiche un toast clair : "Ton lien d'invitation a
  expire. Pas de souci, l'acces est ouvert : cree ton compte ci-dessous."
- Le mode initial 'signup' est choisi dans l'initialiseur du `useState` (pas de
  `setState` dans un effet -> conforme `react-hooks/set-state-in-effect`).

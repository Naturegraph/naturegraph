## Resume

Fix UX critique : un user authentifie qui presse le bouton retour mobile depuis le feed ne doit plus tomber sur la landing page publique.

---

## Changements

### Securite / UX navigation

- **Route `/` Landing protegee par PublicRoute** :
  - Avant : pas de guard, un user auth qui presse back depuis /home tombait sur la landing publique (sort de son contexte app, demande reconnexion implicite, mauvaise UX mobile)
  - Apres : PublicRoute wrapper, redirige automatiquement vers /home (ou /onboarding si incomplet) avec `replace`, donc le back button ne ramene plus sur la landing
  - Impact : navigation mobile fluide, l user reste dans l app meme apres multiples back

### Comportement attendu post-fix

| Scenario                           | Avant                         | Apres                                           |
| ---------------------------------- | ----------------------------- | ----------------------------------------------- |
| User auth sur /home, press back    | Landing publique (mauvais)    | /home reste (PublicRoute redirige `/` to /home) |
| User auth sur /profile, press back | /home                         | /home (inchange, deja propre)                   |
| User auth tape naturegraph.ca      | Landing publique (incoherent) | Auto-redirige /home                             |
| User non-auth tape naturegraph.ca  | Landing (correct)             | Landing (correct, pas de guard si pas auth)     |

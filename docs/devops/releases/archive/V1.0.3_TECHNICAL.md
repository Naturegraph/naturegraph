## Changements

### Securite DB (lockdown SECURITY DEFINER)

- 36 fonctions SECURITY DEFINER auparavant executables par anon + authenticated
  via REST RPC (heritage default Postgres grant PUBLIC).
- Avant : 80+ advisor warnings, surface d attaque large.
- Apres : REVOKE EXECUTE FROM PUBLIC + GRANT explicite par role :
  - 18 triggers : aucun grant public (service_role uniquement)
  - 2 admin RPCs (anonymize_beta_signup_log, generate_beta_keys) : service_role
  - 5 auth-only (claim_beta_access_key, clear_user_location, update_user_location,
    release_beta_access_key, nearby_posts) : authenticated
  - 5 RLS helpers (can*see*\*, is_admin, is_internal_user, is_notif_enabled) : authenticated
  - 3 publics gardes (check_beta_access_key_validity, search_cities, reverse_geocode_city)
- Resultat : 80+ -> 25 warnings (toutes intentionnelles documentees inline migration).

### Fix bug "Claire" (claim atomique beta key)

- Symptome : code beta consomme (current_uses++, used_at=NOW) mais
  used_by_user_id reste NULL. Admin aveugle sur qui a utilise quel code.
- Cause : `claim_beta_access_key(p_code)` n ecrivait jamais used_by_user_id.
- Fix SQL : nouvelle signature `claim_beta_access_key(p_code text, p_user_id uuid DEFAULT NULL)`
  avec fallback sur `auth.uid()` si p_user_id absent. Ecrit `used_by_user_id = COALESCE(...)`.
- Fix Edge Function `validate-beta-key` v2 : extrait `sub` du JWT Authorization header,
  passe `p_user_id: authUserId` au RPC.
- Backfill manuel : `NG-NJQ6-Z3XZ` lie a maheux.nael@gmail.com (orphan historique).
- Etat DB : 2 cles properly_linked, 0 orphan.

### Cleanup DB

- DROP 17 indexes inutilises (features dormantes ou redondants) :
  idx_media_license, idx_profiles_email/country/subscription/is_internal_false,
  idx_posts_country/habitat, idx_community_photos_active, idx_reports_status_pending,
  idx_beta_signup_log_outcome, idx_fr_cities_department/region/name_exact,
  media_series_idx, media_watermark_pending_idx, support_tickets_status_idx,
  security_audit_log_event_idx.
- KEEP 22 indexes (FK + trigram autocomplete + gist geo) malgre flag "unused"
  (beta tres jeune, stats pg_stat_user_indexes pas encore representatives).
- ANALYZE sur 8 tables chaudes (posts, profiles, media, follows, notifications,
  hidden_posts, blocks, species_master).

## Risques

Faible. Toutes les modifications sont reversibles :

- REVOKE/GRANT : restorable via GRANT TO PUBLIC si regression
- Indexes droppes : recreables (DDL CREATE INDEX dans migration history)
- Extensions : DROP EXTENSION possible mais inutile
- Realtime : `ALTER PUBLICATION DROP TABLE` si charge anormale

- Logs Edge Function validate-beta-key (verifier passing du user_id)

# Release V0.0.7 : tracabilite consentement + durcissement CORS (technique)

> Date : 2026-06-30 · Tag : `v0.0.7` · Branche : `main` (prod)
> Precedent : `v0.0.6`
> Force-logout : NON · Migrations : 1 (a appliquer en prod) · Notif in-app : non

Grappe securite + legal, post-ouverture. Deux sujets clotures : la trace du
consentement legal au signup (NG-038) et la restriction du CORS des Edge
Functions (NG-032, dernier residuel code).

## Tracabilite du consentement legal (NG-038)

- Table `user_legal_consents` : audit immuable (une ligne par user + document +
  version), RLS `authenticated` only (guest-safe NG-032) : insert/select
  restreints a `auth.uid() = user_id`, pas d'update/delete.
- Service `legalConsentService.recordSignupConsent()` : upsert idempotent
  best-effort, appele apres OTP verifie au signup (pas a l'invitation). Constante
  `LEGAL_VERSION` a bumper avec les documents (NG-010).
- `AuthPage` : enregistre le consentement dans la branche signup post-verification.
- Type ajoute a `src/types/supabase.ts` (mirroir de la migration).
- **Migration `20260630_legal_consents.sql` a appliquer en prod** (deja sur dev).
  Best-effort cote client : tant que la table n'existe pas en prod, le signup
  n'est pas casse (try/catch), la trace commence des l'application.

## Durcissement CORS Edge Functions (NG-032)

- Helper partage `supabase/functions/_shared/cors.ts` : `buildCors(req)` avec
  allowlist (naturegraph.ca, naturegraph.fr, beta., previews \*.vercel.app,
  localhost). Origine reflechie si autorisee, sinon origine prod par defaut
  (reponse bloquee cote navigateur). Defense en profondeur : ces functions
  s'authentifient deja par token/secret.
- 5 functions browser-facing adaptees : admin-delete-user, delete-account,
  export-data, send-beta-invite (json() passe en closure), validate-beta-key.
- Laissees telles quelles : weekly-species-digest (cron x-cron-secret) et
  send-waitlist-confirmation (appelee par la base, pas de CORS).
- **A deployer pour prise d'effet** : `supabase functions deploy <name>` (dev +
  prod). Sans deploiement, les anciennes functions (`*`) continuent de tourner :
  aucune rupture. Si une origine d'app legitime manque -> l'ajouter a
  `STATIC_ALLOWED`.

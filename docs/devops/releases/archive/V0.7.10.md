# V0.7.10 : socket morte au retour d'arriere-plan -> reload automatique

## Confirmation Sentry (prod, release 0.7.9)

Avec 0.7.9, le bouton n'est plus mort (spinner immediat), et Sentry en prod montre
enfin la sequence exacte du va-et-vient sur mobile (Chrome Android) :

1. `Echec silencieux : ...(session-timeout-on-continue)` -> `assertActiveSession`
   atteint son timeout 8 s (l'appel auth pendait).
2. `Error: Timeout creation du post apres 20s` -> le POST `createPost` pend 20 s,
   retry (`createPost.retry {attempt: 2, kind: timeout}`), re-pend 20 s, echoue.
3. `Echec silencieux : ...(deja-en-cours)` -> 2e tap pendant que ca tourne.

## Cause racine

Au retour d'arriere-plan sur mobile, la radio coupe la **socket TCP** vers Supabase
**sans geler le JS**. React repond donc normalement (le spinner s'affiche), mais
**toutes les requetes reseau PENDENT** (auth + insert + meme le retry, sur la meme
socket morte) jusqu'au timeout OS. Seule une **relance complete** de l'app (nouvelles
sockets) debloquait. `resumeRecovery` ne rechargeait que sur **gel du JS** (heartbeat)
-> il ne couvrait pas ce cas "socket morte sans gel".

## Le fix

`resumeRecovery.ts` : au retour au premier plan apres une absence >= 3 s (et sans
gel detecte), on **SONDE le backend** : un `GET` leger sur `${SUPABASE_URL}/auth/v1/health`
borne par un AbortController (4 s), en `no-cors` (on veut juste savoir si le serveur
REPOND). Si la sonde pend / rejette = socket morte -> **on recharge la page une fois**
(garde anti-boucle 10 s). Le rechargement repart sur des sockets neuves : c'est la
"relance complete" qui debloquait, desormais automatique. Le brouillon (NG-004) + les
photos (NG-038) sont restaures : aucune perte de saisie.

Si la sonde repond (backend vivant), aucun reload : on garde le comportement existant
(refetch doux si l'absence a depasse 2 min).

Complet avec 0.7.8/0.7.9 :

- 0.7.8 : retry reseau du POST (Load failed iOS), auteur = session vivante.
- 0.7.9 : verrou + spinner immediats, timeout 8 s sur la verif de session.
- 0.7.10 : reload automatique quand la socket backend est morte au retour.

## Fichiers

- `src/lib/resumeRecovery.ts` : sonde de vivacite backend + reload si injoignable
  au retour d'arriere-plan.

## Pourquoi c'est sur

- Le reload ne se declenche QUE si le backend est reellement injoignable (sonde
  bornee a 4 s) ET apres une absence >= 3 s : pas de reload sur bascule eclair ni
  sur connexion saine. Garde anti-boucle 10 s (partagee avec les autres reloads).
- Desktop : backgrounder un onglet ne tue quasi jamais la socket -> sonde OK -> pas
  de reload. Comportement inchange.

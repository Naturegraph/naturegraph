# V0.7.14 : recherche resiliente + self-healing du client bloque

## Contexte

Retour Nicolas : "recherche d'espece / de localisation : on peut taper une fois et
c'est tout ; quand on veut modifier la recherche, plus rien ne se passe, il faut
refresh ou fermer l'app."

## Diagnostic

Les QUATRE surfaces de recherche (SearchPanel global, especes EncounterStep2,
CityAutocomplete, localisation EncounterStep3) sont structurellement correctes :
modifier la saisie re-declenche bien la recherche (debounce + re-fetch). Le service
`searchService` a deja timeout 15 s + retry cold-start + retry sur token expire.

Le symptome "on tape une fois puis plus rien, il faut fermer l'app" est donc **le
meme blocage supabase-js** que le va-et-vient : le client se retrouve bloque (souvent
au retour d'arriere-plan) et les RPC de recherche PENDENT. Le timeout evite le loader
infini, mais la recherche reste inutilisable jusqu'a une relance complete.

## Le fix

1. **`searchProfiles` borne** : il faisait un `await` nu SANS timeout -> il pouvait
   pendre indefiniment sur un client bloque. Passe sur le meme `rpcWithRetry`
   (timeout 15 s + retry cold-start + retry token expire) que la recherche d'especes.

2. **Self-healing du client bloque** (nouvelle primitive reutilisable) :
   `probeBackendAndReloadIfStalled()` dans `resumeRecovery.ts` sonde `getUser()` et,
   si le client ne repond plus, recharge la page (client + sockets neufs, garde
   anti-boucle 10 s, brouillon + panneau restaures). Branchee dans `rpcWithRetry` :
   quand une RPC de recherche timeoute APRES tous ses retries, on sonde et on se
   recharge tout seul -> la recherche remarche **sans que l'utilisateur ait a fermer
   l'app**. Distinct de la reprise d'arriere-plan : couvre aussi un stall en cours de
   session.

## Fichiers

- `src/services/searchService.ts` : `searchProfiles` sur `rpcWithRetry` ; declenche
  `probeBackendAndReloadIfStalled` sur timeout persistant.
- `src/lib/resumeRecovery.ts` : export `probeBackendAndReloadIfStalled` (self-healing
  reutilisable, aussi utilisable plus tard pour d'autres chemins critiques).

## Note

Aucune reecriture des composants de recherche (ils sont corrects) : on traite la
cause reelle (client bloque) et on la rend auto-recuperable. Les echecs de recherche
restent traces dans Sentry (`search.species`, `backend.stalled`).

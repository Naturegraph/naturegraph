# Release V0.0.6 : ouverture de l'acces anticipe (technique)

> Date : 2026-06-30 · Tag : `v0.0.6` · Branche : `main` (prod)
> Precedent : `v0.0.5`
> Force-logout : NON · Migrations : 1 (deja appliquee dev + prod) · Notif in-app : non

Release d'ouverture. Le flag `OPEN_ACCESS_ENABLED` passe a **true** : la beta
fermee et le code d'acces disparaissent. L'app devient accessible a tous depuis
la landing (visiteur sans compte + inscription libre). Aboutissement de NG-029 +
NG-032 (securite) + NG-038 (legal).

## Acces ouvert active (NG-029)

- `OPEN_ACCESS_ENABLED = true` dans `featureFlags.ts`.
- Ecran `/welcome` (saisie du code) **physiquement supprime** (plus de
  `Welcome.tsx`). La route `/welcome` redirige vers `/`.
- `BetaAccessGuard` devient un pass-through (plus de gate). Signup libre depuis
  la landing, sans cle ni claim. `/waitlist` redirige vers `/`.
- Session expiree : redirection vers `/login` (au lieu de l'ancien `/welcome`),
  toast "session expiree" deplace sur l'ecran de connexion.

## Securite (NG-032)

- Code/DB (deja en prod depuis V0.0.5) : honeypot anti-bot sur les formulaires
  auth, RLS guest verifiee (anon bloque en ecriture), REVOKE EXECUTE + search_path
  propres. Audit dans `docs/security/SECURITY_SUPABASE.md` section 10.
- Durcissement dashboard prod (2026-06-30) : secret `waitlist_trigger_secret`
  (Vault + Edge Function, valeur confirmee par empreinte SHA256), leaked-password
  protection ON, Email OTP expiration 120s -> 600s, rate limit emails 100 -> 200/h,
  policy DELETE notifications verifiee (`auth.uid() = user_id`, role authenticated).

## Legal (NG-038)

- Mention d'acceptation au signup : CGU (`/legal`) + politique de confidentialite
  (`/privacy`) + "acces anticipe (phase de test), service fourni tel quel".
  Texte 14px italique, mention d'age retiree de l'affichage (reste dans les CGU).
- Pages legales : passage de "beta privee fermee" a "acces anticipe (phase de
  test)", cadre protecteur conserve.

## Base de donnees

- Migration `20260630_drop_waitlist_confirmation_trigger.sql` : suppression du
  trigger `waitlist_send_confirmation` + sa fonction `trigger_send_waitlist_email`.
  L'email de confirmation waitlist est obsolete en acces ouvert (un import en
  masse ne doit pas spammer). **Deja appliquee sur dev ET prod.** La fonction edge
  `send-waitlist-confirmation` reste deployee mais protegee par le secret.
- NE PAS reappliquer `20260623_waitlist_confirmation_secret.sql` (recreerait la
  fonction supprimee).

## Verifications

  uniquement) · **78 tests verts**. Parcours flag-ON verifie en preview
  (`/welcome` -> landing, signup sans code, mention legale).

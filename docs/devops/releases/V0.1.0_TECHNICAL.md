# Release V0.1.0 : systeme de notifications email intelligent (technique)

> Date : 2026-07-09 · Tag : `v0.1.0` · Branche : `main` (prod)
> Precedent : `v0.0.8`
> Force-logout : NON · Migrations : oui (deja appliquees en prod) · Notif in-app : non
> Ticket : NG-045 (Epic Notifications email)

Premiere MINOR de la phase de prelancement : livraison complete du systeme de
notifications email (8 types E1-E8), construit et teste bout en bout sur le
compte de test avant activation.

## Architecture

Trigger/cron Postgres (pg_cron + pg_net, secret d'auth dans Supabase Vault) ->
Edge Function -> verification preferences (`user_settings.email_notifications`

- `notification_preferences.email_enabled` via RPC `is_email_enabled`) ->
  anti-spam (`email_send_log`) -> Resend API. Cle Resend dediee
  `supabase-edge-notifications`.

## Ce qui part en prod

**Frontend (deploye par cette release) :**

- Heartbeat `profiles.last_active_at` (ActivityHeartbeat + useActivityHeartbeat) :
  requis par E2/E7/E8 (regle "ne pas emailer si deja revenu aujourd'hui").
- Page `/desabonnement` (cible de la redirection de `email-unsubscribe`).
- Fix onboarding : le choix de frequence ecrit `notif_frequency` + `week_goal`
  selon la table de correspondance NG-045.
- Titre "Notifications" cliquable dans la cloche (vers la page complete).

**Backend (deja deploye sur Supabase, references ici) :**

- 10 Edge Functions : `send-notification-email` (dispatcher), `email-unsubscribe`
  (GET redirige + POST un-clic RFC 8058), et 8 jobs (check-activation-emails,
  check-species-milestones, check-social-digest, check-followed-digest,
  check-goal-reminder, check-streak-risk, check-weekly-summary, check-missed-feed).
- Migrations : canal email sur `notification_preferences`, `notifications.emailed_at`,
  `profiles.last_active_at` + RPC `touch_last_active`, table `email_send_log`,
  `is_email_enabled` (opt-out), grants durcis, 8 crons pg_cron (actifs).

## Garde-fous

- Quota 1 email marketing/semaine (categorie `weekly_marketing`, E1-E4 ne se
  cumulent pas), plafonds evenementiels 1/jour (E7/E8), `emailed_at`
  (jamais 2x la meme notif), skip si l'utilisateur est deja revenu aujourd'hui.
- Desabonnement par type + interrupteur global + List-Unsubscribe un-clic.
- **Garde-fou onboarding** (dispatcher) : seuls les profils ayant termine leur
  onboarding recoivent des emails ; les invites-seulement sont exclus.
- `is_email_enabled` : EXECUTE reserve au service_role (durcissement post-audit).

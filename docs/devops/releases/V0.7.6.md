> Base prod : V0.7.5. Aucune migration (la colonne posts.phenomenon existe deja).
> Pas de force-logout. Deux causes racines confirmees par Sentry + tests reels.

---

## 1. Instant Nature : publication debloquee (bug confirme par Sentry)

**Preuve Sentry (release 0.7.5)** : `[postService.createPost] erreur DB: Tag invalide :
max 50 caracteres, lettres/chiffres/tirets uniquement` -> POST /posts **400** ->
"La publication a echoue".

**Cause** : Instant Nature stockait le phenomene dans `posts.tags[0]` = le LIBELLE
(« Coucher / lever de soleil », « Aurore boreale »...). Or `tags` a une contrainte DB
stricte (lettres/chiffres/tirets, 50 car.) que ces libelles (espaces, « / », accents)
**violent** -> 400 -> **TOUTE publication Instant avec un phenomene echouait**. (Rencontre
n'utilise pas de tags -> marchait ; d'ou la difference constatee.)

**Fix** : on utilise la VRAIE colonne `posts.phenomenon` (VARCHAR 255, libre, deja
exposee dans la vue `posts_public`) au lieu du workaround `tags`.

- `CreatePostPayload.phenomenon` ajoute ; `createPost` l'insere (spread payload).
- ContributeInstantPanel : `phenomenon: label`, `tags: []`.
- Feed (mapper partage) : lit `item.phenomenon` (fallback `tags[0]` pour les anciens
  posts crees via le workaround).
- Mode edition : lit la colonne `phenomenon` (fallback tags[0]).

## 2. Va-et-vient mobile : detection de gel FIABLE (bouton mort)

Les V0.7.3/0.7.4/0.7.5 ne reglaient pas le va-et-vient sur **PWA mobile** : mon
detecteur reposait sur `visibilitychange` / `pageshow(persisted)`, **peu fiables en
PWA iOS/Android standalone** (parfois pas emis au reveil) -> le rechargement ne se
declenchait jamais.

**Fix** (`resumeRecovery.ts`) : la detection repose desormais sur le **battement de
coeur lui-meme**. Un `setInterval` (2 s) est GELE en arriere-plan ; au degel, le
PREMIER tick voit un grand ecart depuis le dernier battement (>= 8 s) = preuve que le
JS a ete suspendu -> **reload**. L'intervalle reprend TOUJOURS au degel, independamment
de tout evenement -> fiable meme quand `visibilitychange` ne fire pas. On ne recharge
que si l'app est au premier plan (pas de faux positif desktop : timers de fond clampes
a ~2 s les 5 premieres minutes). Le brouillon (NG-004) + photos (NG-038) restaurent la
saisie -> zero perte. `visibilitychange`/`pageshow` restent comme declencheurs
immediats (plus rapides) quand ils fire.
